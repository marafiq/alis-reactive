The runtime is a Reactive Plan interpreter. It reads the JSON plan produced by the
C# builders, composes the current Active Plan, wires declared triggers, and
executes the declared reactions. It does not infer missing plan shape or add
fallback behavior.

## Module structure

```
Alis.Reactive.Assets/runtime/
├── root.ts                         waits for DOM readiness, registers host plugins, boots discovered plans
├── lifecycle/
│   ├── boot.ts                     wires validation and behaviors; runs page-ready after listeners exist
│   ├── applied-plans.ts            owns boot snapshots, loaded partial slots, and Active Plan recomposition
│   ├── merge-policy.ts             composes boot and slot plans into one Active Plan
│   ├── component-merge.ts          merges component records by role and slot ownership
│   └── object-contracts.ts         merges BrowserObjectContract fragments
├── execution/
│   ├── triggers/trigger.ts         wires page-ready, document, component, server-push, and SignalR triggers
│   ├── reactions/execute.ts        dispatches reaction graphs
│   ├── requests/http.ts            validates, gathers input, fetches, and routes responses
│   ├── requests/gather.ts          resolves RequestInput values
│   ├── partials/inject.ts          injects HTML and loads or unloads embedded partial plans
│   └── realtime/                   server-push and SignalR connection handling
├── browser-objects/                component/plugin runtime object access, paths, shapes, and execution context
├── values/evaluate.ts              evaluates ValueExpression from literal, read, object, array, and array-op nodes
├── conditions/                     evaluates ConditionGraph nodes
├── validation/                     live validation and server validation display
├── events/                         native and Fusion component event resolution
├── plugins/                        host plugin catalog
├── shared/                         assertNever, shape conversion, and wire helpers
└── types/plan.ts                   generated TypeScript contract from the C# plan domain
```

## Boot Flow

`root.ts` starts once the document is ready. It drains queued host-page plugins,
initializes built-in browser objects such as confirm and native action links,
parses every `[data-reactive-plan]` script, composes boot plans by `planId`, and
passes each Active Plan to `boot()`.

`boot.ts` wires two things:

1. Live validation for components that declare a validation container.
2. Behaviors from the Active Plan.

Behavior wiring is intentionally two-phase. Non-`page-ready` triggers are wired
first, then `page-ready` behaviors run. That preserves event chains where a
page-ready reaction dispatches a document event that another behavior listens
for.

## Active Plan Composition

`applied-plans.ts` owns the runtime plan state:

| State | Purpose |
|-------|---------|
| Boot snapshot | Immutable copy of the plan discovered during first boot. |
| Partial slot load | Plans loaded into one partial slot, plus the slot's `AbortController`. |
| Active Plan | Recomposition of the boot snapshot plus currently loaded slot plans. |

When a partial slot loads, the runtime snapshots the incoming plans, recomposes
affected Active Plans, wires the new slot behaviors, and wires validation for
components introduced by the slot. When a slot unloads, its `AbortController`
removes the slot's listeners and the affected Active Plans are recomposed
without that slot.

## Trigger Wiring

Each `Behavior` has `startsWhen` plus a `reaction`. `trigger.ts` wires the
current trigger kinds:

| Trigger kind | Runtime behavior |
|--------------|------------------|
| `page-ready` | Runs immediately or on `DOMContentLoaded`. |
| `document-event` | Adds a `document` listener and uses `CustomEvent.detail` when present. |
| `component-event` | Resolves the component event channel and wires the component event source. |
| `server-push` | Opens an SSE stream through `EventSource`. |
| `signalr` | Wires a SignalR hub method. |

`trigger.ts` is also the reaction error boundary. Sync failures are logged
inside the event turn; async failures are logged when their promise rejects.
Pure sync reactions must stay sync so component event payload mutations remain
visible to the vendor event handler.

## Reaction Execution

`execute.ts` dispatches the current `ReactionGraph` kinds:

| Reaction kind | Runtime behavior | Sync/async expectation |
|---------------|------------------|------------------------|
| `set` | Sets a component/plugin/payload property. | Sync |
| `call` | Calls a component/plugin/payload method. | Sync |
| `dispatch` | Dispatches a document `CustomEvent`. | Sync |
| `inject` | Injects HTML into a partial slot and applies embedded plans. | Sync boundary, may load plan state |
| `show-validation-errors` | Renders server validation errors into the validation container. | Sync |
| `sequence` | Executes each child reaction in order, awaiting only after the first async child. | Sync until an async child appears |
| `branch` | Evaluates cases in order and runs the matching reaction. | Sync unless a condition or selected reaction is async |
| `request` | Validates, gathers request input, sends fetch, and routes the response. | Async |
| `parallel` | Runs child reactions concurrently and optionally runs an `on-settled` reaction. | Async |

This is one reaction graph, not a command layer. Component writes, method calls,
document dispatch, partial injection, requests, and validation display are all
reaction nodes.

## Value Evaluation

`values/evaluate.ts` is the shared `ValueExpression` evaluator used by
execution, gather, validation, and condition evaluation.

| Value expression | Runtime behavior |
|------------------|------------------|
| `literal` | Applies the declared shape to the literal value. |
| `read` | Reads from component/plugin object contracts, URL parameters, payload scopes, DOM sources, or element scope. |
| `object` | Evaluates fields and applies the declared object shape. |
| `array` | Evaluates items and applies the declared array shape. |
| `array-op` | Runs the declared array operation with element-scoped predicates. |

DOM reads are the explicit DOM boundary. Component and plugin reads go through
`RuntimePlan.objectForSource()`, so contract access stays centralized.

## Request Input

`requests/gather.ts` resolves `RequestInput` through the same `evaluateValue`
path used by reactions and conditions. Authored assignments write to payload,
header, or route-param targets. `all-registered-inputs` walks mounted registered
inputs in the Active Plan and writes their bound values through
`request-payload-writer.ts`.

Route params and headers must serialize to scalar wire values. Missing mounted
registered inputs are skipped because unloaded partial slots are valid Active
Plan state.

## Exhaustiveness

The runtime uses `assertNever()` where generated union kinds cross module
boundaries. If the C# plan model adds a new kind without a TypeScript handler,
the TypeScript compiler and runtime both point to the missing handler.

Important exhaustiveness points:

| Module | Union checked |
|--------|---------------|
| `execution/triggers/trigger.ts` | `startsWhen.kind` |
| `execution/reactions/execute.ts` | `reaction.kind`, `parallel.completion.kind` |
| `values/evaluate.ts` | `valueExpression.kind`, `readExpression` source/access |
| `execution/requests/gather.ts` | `requestInput.kind`, assignment target, registered input selection |
| `conditions/conditions.ts` | condition graph kinds |
