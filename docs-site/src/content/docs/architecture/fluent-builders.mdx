The fluent builders are the typed authoring layer.

They do not execute browser behavior. They build the V2 contract that the browser runtime will execute later.

```d2
direction: right

authoring: "Developer writes\nfluent C#" {
  shape: rectangle
}
builders: "Typed builders\nactions, requests,\npredicates, bindings" {
  shape: rectangle
}
plan: "V2 plan model\ncontracts, objects,\nbindings, workflows" {
  shape: rectangle
}
runtime: "Browser runtime\nresolves and executes" {
  shape: rectangle
}

authoring -> builders
builders -> plan
plan -> runtime
```

## Boundary rule

The C# side may:

- capture intent
- keep the DSL compile-time safe
- render the V2 document

The C# side may not:

- touch the DOM
- execute HTTP
- evaluate browser events
- invent runtime state

The runtime may:

- resolve objects
- resolve members
- evaluate predicates
- execute actions

The runtime may not:

- extend the schema
- guess missing values
- recreate deleted authoring concepts

## What the builders produce

They produce V2-native concepts:

- capability contracts
- runtime objects
- bindings
- workflows
- predicates
- actions
- request plans

They lower fluent intent directly into the V2 plan model.
