A page can host multiple plans. A form might use `ReactivePlan<ResidentModel>`. A sidebar might use `ReactivePlan<NotesModel>`. A partial view might use `ResolvePlan<ResidentModel>` to merge into the parent plan. V2 keeps those cases explicit and deterministic.

## Multiple independent plans

Each `ReactivePlan<TModel>()` call creates its own plan document with its own `planId`. At page load, `root.ts` discovers all `[data-reactive-plan]` elements and boots each plan independently.

```d2
direction: right

page: "Page load\nroot.ts discovers all\n[data-reactive-plan] elements" {
  shape: rectangle
  style.fill: "#e8f0fe"
  style.stroke: "#4285f4"
  style.font-size: 16
}
plan1: "Plan A\nResidentModel\nOwn contracts/objects\nbindings/workflows" {
  shape: rectangle
  style.fill: "#fef7e0"
  style.stroke: "#f9ab00"
  style.font-size: 16
}
plan2: "Plan B\nNotesModel\nOwn contracts/objects\nbindings/workflows" {
  shape: rectangle
  style.fill: "#e6f4ea"
  style.stroke: "#34a853"
  style.font-size: 16
}

page -> plan1: boot()
page -> plan2: boot()
```

Plans with different `planId` values are completely independent. A document dispatch such as `Dispatch("save")` is still visible across plans because it targets `document`, but objects, bindings, and workflows do not leak across plan boundaries.

## Partial view composition — same model

When a partial view shares the parent's model, use `Html.ResolvePlan<TModel>()`. Multiple plan elements with the same `planId` are composed before boot:

```d2
direction: right

parent: "Parent view\nReactivePlan<ResidentModel>\nsource A" {
  shape: rectangle
  style.fill: "#e8f0fe"
  style.stroke: "#4285f4"
  style.font-size: 16
}
partial: "Partial view\nResolvePlan<ResidentModel>\nsource B" {
  shape: rectangle
  style.fill: "#fef7e0"
  style.stroke: "#f9ab00"
  style.font-size: 16
}
merged: "Composed plan\nplanId: ResidentModel\ncontracts + objects + bindings + workflows" {
  shape: rectangle
  style.fill: "#e6f4ea"
  style.stroke: "#34a853"
  style.font-size: 16
}

parent -> merged: same planId
partial -> merged: same planId
```

Initial composition merges:

- shared contracts by idempotent contract key
- runtime objects by object name
- bindings by binding path
- workflows by concatenation

That is why `IncludeAll()` gathers values from components declared in both the parent and the partial: they end up in one composed binding set before boot.

## AJAX-loaded partials — runtime merge

When a partial view is loaded via AJAX, the injected HTML may contain its own `[data-reactive-plan]` element. `inject.ts` discovers it and calls `mergePlan()`:

```d2
direction: right

fetch: "HTTP response\nHTML with embedded\n[data-reactive-plan]" {
  shape: rectangle
  style.fill: "#e8f0fe"
  style.stroke: "#4285f4"
  style.font-size: 16
}
inject: "inject.ts\nInsert HTML into container\nDiscover embedded plan" {
  shape: rectangle
  style.fill: "#fef7e0"
  style.stroke: "#f9ab00"
  style.font-size: 16
}
merge: "mergePlan()\nregister source-owned objects\nbindings/workflows" {
  shape: rectangle
  style.fill: "#e6f4ea"
  style.stroke: "#34a853"
  style.font-size: 16
}

fetch -> inject -> merge
```

`mergePlan()` does not resurrect a second schema or rebootstrap everything blindly. It registers the new plan fragment into the already booted V2 state, wires the new workflows, and keeps ownership by `sourceId` so removal stays deterministic.

## How plans stay isolated

| Concern | Behavior |
|---------|----------|
| Component IDs | Unique per `Html.InputField` expression |
| Document dispatch | `Dispatch` fires a document event that any plan may subscribe to |
| Gather scope | `IncludeAll` gathers from the plan's own binding set only |
| Validation scope | `Validate<T>` resolves fields through the plan's own bindings |
| Partial cleanup | source-owned objects, bindings, and workflows are removed with the partial |

## When to use which

| Scenario | API | Result |
|----------|-----|--------|
| Main view form | `Html.ReactivePlan<TModel>()` | New plan with its own `planId` |
| Partial view, same model | `Html.ResolvePlan<TModel>()` | Composes into the parent plan |
| Partial view, different model | `Html.ReactivePlan<TOtherModel>()` | Independent plan |
| AJAX-loaded content | `into` action | Runtime merge via `mergePlan()` |
