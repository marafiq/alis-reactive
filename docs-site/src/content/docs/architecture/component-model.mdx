A native checkbox is `el.checked`. A Syncfusion date picker is `el.ej2_instances[0].value`. The runtime handles both through BrowserObject contracts. This page explains how.

For the general execution model, see [Runtime](../runtime/).

## Component Metadata

Each component declares the metadata needed to register a component object in the
Reactive Plan.

| Field | Purpose | Example |
|-------|---------|---------|
| **Vendor** | Which root object to resolve | `"native"` or `"fusion"` |
| **ValueMember** | Which member gather and validation read for model-bound inputs | `"value"`, `"checked"` |
| **ComponentType** | What kind of component | `"textbox"`, `"datepicker"` |
| **BrowserObjectContract** | Which properties, methods, and events the runtime may use | `value`, `focus`, `change` |

When you write `Html.InputField(plan, m => m.DueDate).FusionDatePicker(...)`,
the builder registers a Fusion component with a `ValueMember` of `"value"`.
When a pipeline calls `SetValue`, `FocusIn`, or `Value()`, the C# side adds the
needed BrowserObject contract member to the plan.

## Vendor resolution — one function, any vendor

```d2
direction: right

element: "DOM Element" {
  shape: rectangle
  style.fill: "#f0f0f0"
  style.stroke: "#666"
  style.font-size: 18
}

native_root: "native\nroot = element" {
  shape: rectangle
  style.fill: "#e8f0fe"
  style.stroke: "#4285f4"
  style.font-size: 18
}

fusion_root: "fusion\nroot = el.ej2_instances[0]" {
  shape: rectangle
  style.fill: "#fef7e0"
  style.stroke: "#f9ab00"
  style.font-size: 18
}

contract: "BrowserObjectContract\nproperty read/write\nmethod call" {
  shape: rectangle
  style.fill: "#e6f4ea"
  style.stroke: "#34a853"
  style.font-size: 18
}

element -> native_root: vendor {
  style.stroke: "#4285f4"
}
element -> fusion_root: vendor {
  style.stroke: "#f9ab00"
}
native_root -> contract {
  style.stroke: "#34a853"
}
fusion_root -> contract {
  style.stroke: "#34a853"
}
```

`browser-objects/component-driver.ts` resolves the vendor root. Native components
use the element itself; Fusion components use the Syncfusion EJ2 instance. After
that, `RuntimeObject` applies the declared BrowserObject contract member.

## Every interaction, one pattern

| Interaction | Plan carries | Runtime does |
|-------------|-------------|-------------|
| **Read** (gather, conditions) | component source + member contract | `RuntimeObject.read(member)` |
| **Write** (`SetValue`, `SetChecked`) | `set` reaction + property contract | `RuntimeObject.set(member, value)` |
| **Call** (`DataBind`, `ShowPopup`) | `call` reaction + method contract | `RuntimeObject.call(member, args)` |
| **Wire event** (`.Reactive`) | `startsWhen: component-event` + event contract | wire the component event channel |

## Adding a new component — zero runtime changes

The component declares its vendor, optional input `ValueMember`, and
component-specific BrowserObject members through typed extension methods. The
runtime already knows how to resolve vendors and execute `set`, `call`, and
component-event reactions. For the full slice pattern, see [The Vertical Slice](../vertical-slice/).
