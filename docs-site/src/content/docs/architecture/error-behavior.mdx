The runtime follows one principle: **fail fast at real boundaries, no invented
fallbacks.** The C# framework owns generated plan shape. The TypeScript runtime
executes that plan and reports failures when execution crosses browser,
component, plugin, network, payload, or generated-union boundaries.

## Error Boundary

`execution/triggers/trigger.ts` is the reaction error boundary. Each trigger
runs its reaction inside `runReaction()`:

```d2
direction: right

trigger: "trigger fires" {
  shape: rectangle
  style.fill: "#e8f0fe"
  style.stroke: "#4285f4"
  style.font-size: 16
}
execute: "executeReaction()" {
  shape: rectangle
  style.fill: "#fef7e0"
  style.stroke: "#f9ab00"
  style.font-size: 16
}
sync: "sync throw\nlogged in current event turn" {
  shape: rectangle
  style.fill: "#fce8e6"
  style.stroke: "#ea4335"
  style.font-size: 16
}
async: "promise rejection\nlogged when rejected" {
  shape: rectangle
  style.fill: "#fce8e6"
  style.stroke: "#ea4335"
  style.font-size: 16
}

trigger -> execute
execute -> sync: sync failure
execute -> async: async failure
```

This boundary protects other listeners from one failed behavior. It also keeps
sync reactions sync: a Syncfusion event payload mutation such as setting cancel
state must complete before the vendor event handler continues.

## Fail-Fast Boundary Errors

Examples of current boundary errors:

| Module | Boundary | Example message |
|--------|----------|-----------------|
| `root.ts` | Empty or malformed `[data-reactive-plan]` script. | `[alis] failed to parse plan JSON from [data-reactive-plan] element: ...` |
| `browser-objects/runtime-plan.ts` | Component key missing from the Active Plan. | `[alis] component not active in Active Plan: {componentKey}` |
| `browser-objects/runtime-plan.ts` | Component element missing from the DOM. | `[alis] element not found: {componentId}` |
| `browser-objects/component-driver.ts` | Vendor driver missing or duplicate. | `[alis] component runtime already registered for vendor "{vendor}"` |
| `plugins/catalog.ts` | Plugin not registered, duplicate, invalid name, or invalid instance. | `[alis] plugin not found: "{name}"` |
| `values/evaluate.ts` | DOM source element missing. | `[alis] dom source element "{id}" not found` |
| `execution/reactions/execute.ts` | Payload mutation targets null or non-object payload scope. | `[alis] cannot set property on null payload (scope: ...)` |
| `execution/requests/gather.ts` | Route parameter is null or cannot serialize as a scalar. | `[alis] route param "{name}" evaluated to null; cannot build URL` |
| `execution/requests/request-payload-writer.ts` | File object sent through an unsupported body format. | `[alis] File objects require form-data body format` |
| `conditions/conditions.ts` | Confirm guard used without the confirm dialog helper. | `[alis] confirm condition requires @Html.FusionConfirmDialog() in layout` |

These errors point at the boundary that failed instead of hiding the issue behind
a fallback path.

## Exhaustiveness Checks

The runtime uses `assertNever()` from `shared/assert-never.ts` for generated
union kinds. If the C# plan model adds a new kind without a TypeScript handler,
the missing handler fails with `[alis] Unhandled {context}: {kind}`.

Current exhaustiveness points include:

| Module | Generated union checked |
|--------|-------------------------|
| `execution/triggers/trigger.ts` | `startsWhen.kind` |
| `execution/reactions/execute.ts` | `reaction.kind`, `parallel.completion.kind`, branch guard kind |
| `values/evaluate.ts` | `valueExpression.kind`, read source/access kinds |
| `execution/requests/gather.ts` | request input kind, assignment target, registered input selection |
| `execution/requests/request-payload-writer.ts` | request body format, HTTP method, request input item/path segment |
| `conditions/compare-engine.ts` | condition kinds and comparison operators |
| `validation/rule-engine.ts` | validation rule and comparison kinds |

## What The Runtime Does Not Do

- **No generated-plan validation layer.** Generated plan shape is owned by the
  C# plan domain and generated TypeScript contract.
- **No fallback component/plugin lookup.** Runtime object access uses the Active
  Plan and registered browser object contracts.
- **No HTTP retry policy.** A failed `fetch()` follows the declared request error
  route. Realtime transports are different: SSE and SignalR use their transport
  reconnect behavior.
- **No silent component update skipping.** Missing components, missing DOM
  elements, missing plugins, and invalid payload mutation targets are developer
  errors.
- **No global `window.onerror` handling.** Trigger wiring logs reaction failures
  through the runtime trace boundary.
