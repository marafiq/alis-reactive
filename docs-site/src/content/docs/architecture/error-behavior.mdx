The runtime follows one principle: **fail fast, no fallbacks.** If something is wrong, the runtime throws immediately with a clear message. It never guesses, never silently skips, and never translates an old shape into the new one.

## Error boundary

The runtime has one workflow boundary in `trigger.ts`. Each subscription invokes `executeAction()` and logs failures without stopping other subscriptions.

```d2
direction: right

listener: "Subscription fires\n(event, dom-ready, live channel)" {
  shape: rectangle
  style.fill: "#e8f0fe"
  style.stroke: "#4285f4"
  style.font-size: 16
}
execute: "executeAction()\nRuns the workflow action" {
  shape: rectangle
  style.fill: "#fef7e0"
  style.stroke: "#f9ab00"
  style.font-size: 16
}
catch: ".catch()\nLogs error, continues\nOther subscriptions unaffected" {
  shape: rectangle
  style.fill: "#fce8e6"
  style.stroke: "#ea4335"
  style.font-size: 16
}

listener -> execute
execute -> catch: if rejected {
  style.stroke: "#ea4335"
  style.stroke-dash: 3
}
```

This means one broken workflow does not take down unrelated workflows. The failure is contained to the subscription that threw.

## Fail-fast errors

Every error throws with an `[alis]` prefix and specific context.

| Module | Condition | Error shape |
|--------|-----------|-------------|
| `execute.ts` | Target object or member cannot be resolved | `[alis] ...` with object/member context |
| `contracts.ts` | Syncfusion instance not initialized | `[alis] no vendor root for "{id}" (vendor: fusion) — is the component initialized?` |
| `contracts.ts` | Unknown resolver or malformed member path | `[alis] ...` with resolver/member details |
| `contracts.ts` | Object element not in DOM | `[alis] element not found: {id}` |
| `trigger.ts` | Subscription target not in DOM at wire time | `[alis] element not found: {elementId}` |
| `root.ts` | Malformed plan JSON | `[alis] failed to parse plan JSON from [data-reactive-plan] element: {parseError}` |

These errors are actionable. Each one points at a missing object, bad contract, or malformed payload rather than hiding the fault behind retries or default behavior.

## Exhaustiveness checks

The runtime uses `assertNever()` to catch unhandled discriminated unions at both compile time and runtime.

| Module | What it checks |
|--------|----------------|
| `execute.ts` | `action.kind` — sequence, branch, parallel, set, call, dispatch, request, inject, or show-validation-errors |
| `values.ts` | `value.kind` — every supported V2 value expression |
| `contracts.ts` | `member.kind` — property or method |
| `trigger.ts` | `subscription.kind` — dom-ready, document-event, object-event, server-push, or signalr |

If a new V2 kind is added without a corresponding runtime handler, `assertNever()` throws: `[alis] Unhandled {context}: {kind}`.

## What the runtime does not do

- No retry fallback. A failed request does not silently retry.
- No legacy compatibility path. The runtime accepts V2 only.
- No wide DOM scanning. Objects resolve by explicit `elementId`.
- No partial boot recovery. Malformed plan payloads stop that boot path.
- No hidden error sink. Failures surface through the subscription boundary and structured logs/traces.

## Observability

Tracing follows a W3C / OTel-style shape:

- request spans carry HTTP attributes such as `http.request.method` and `url.full`
- outgoing requests propagate `traceparent`
- request lifecycle events are recorded on the active span
- logs are structured with severity metadata instead of free-form fallback logging

The runtime stays intentionally dumb: explicit contract resolution, explicit action execution, explicit tracing.
