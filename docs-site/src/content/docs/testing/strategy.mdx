Every feature is proved at three layers.

```d2
direction: down

layer1: "C# tests\nplan rendering and schema" { shape: rectangle }
layer2: "TypeScript tests\nruntime execution in jsdom" { shape: rectangle }
layer3: "Playwright tests\nreal browser behavior" { shape: rectangle }

layer1 -> layer2
layer2 -> layer3
```

## Layer 1: C# tests

C# tests prove that authoring produces the correct V2 document.

They should check:

- contracts
- objects
- bindings
- workflows
- schema validity

## Layer 2: TypeScript tests

TypeScript tests prove that the runtime executes the rendered V2 document correctly.

They should check:

- object resolution
- member reads and writes
- predicate evaluation
- request execution
- partial merge and cleanup
- validation by binding

## Layer 3: Playwright tests

Playwright tests prove the full system in a browser:

- Razor authoring
- rendered JSON
- runtime boot
- component behavior
- real browser events

## Test design rules

- Prefer vertical slices over central god-helpers.
- Test behavior, not private internals.
- Delete outdated tests when the model changes instead of teaching both systems.
- If a test name uses removed vocabulary, rename it.
- If a helper hides too much behavior, split it.
