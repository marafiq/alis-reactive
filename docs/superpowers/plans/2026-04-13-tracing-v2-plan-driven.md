# Tracing v2 — Plan-Driven, Encapsulated, Event-Only API

> **For the next session:** This plan replaces the abandoned first attempt on branch `tracing-module-otel-standard-as-first-class-citizen-in-ts-runtime` (PR #107). Do **not** merge that branch. Read its lessons below, then start fresh from `release/1.0.0-preview1`.

**Goal:** A tracing module where the runtime is a dumb visitor of the plan, tracing is a cross-cutting observer of that same walk, and the developer writes only `tracer("scope").info("event.name", { data })` — no Span, no lifecycle, no ctx threading, no flush.

**Status of abandoned branch:** Keep `PR #107` and branch open as a learning artifact. Do not delete. Reference it for what NOT to do.

## Lessons From the Abandoned Branch

Before touching new code, internalize these. Every one was a real cost paid in review rounds.

### 1. Manual span lifecycle is a trap

The first attempt exposed `Span` as a first-class API with manual `end("ok")` / `end("error")` calls. Every entry point (trigger, native-action-link, server-push, signalr) had ~20 lines of:

```typescript
const span = getRootSpan().child("trigger.page-ready", { ... });
const scoped = t.withSpan(span);
try {
  const result = executeReaction(reaction, plan, ctx);
  if (result instanceof Promise) {
    result.then(() => span.end("ok"), err => { scoped.error("...", {...}, err); span.end("error"); });
  } else {
    span.end("ok");
  }
} catch (err) {
  scoped.error("...", {...}, err);
  span.end("error");
}
```

**Four files duplicated this pattern.** Every Codex xhigh review round caught at least one missed `end()` path. I added an idempotency guard to paper over the double-end risk. Idempotency guards are usually a sign the API shape is wrong.

**Takeaway:** If the dev has to remember to end a resource, the API is wrong. Wrap the lifecycle inside the framework.

### 2. `ctx.span` as a back-channel was invisible plumbing

`ExecContext.span?: Span` was a field the runtime read for HTTP traceparent injection. Four entry-point files had to remember to populate it. The first migration pass missed three of them — HTTP traceparent only worked from `trigger.ts`, silently failed from `native-action-link/server-push/signalr`. Codex xhigh caught it.

**Takeaway:** Invisible cross-cutting state in a user-visible type guarantees someone will forget to populate it. Keep cross-cutting state inside the tracing module itself.

### 3. Playwright console greps hid real visual bugs

80 vitest + 225 C# unit + 823 Playwright tests all passed, but:

- Trigger spans rendered under `[alis:boot]` instead of `[alis:trigger]` because child spans inherited parent's scope string. Never scoped correctly across files.
- Every log line printed its data object twice (inline JSON + expandable Object arg) because I wanted Playwright greppability AND DevTools expandability and did both. Visual noise.

Playwright's `msg.Text` substring matching didn't care — it found `[alis:boot]` and the data substring either way. I only caught these by opening Chrome and looking.

**Takeaway:** **Open the browser.** Playwright grep is a substring oracle, not a visual one. Every new logging / tracing feature must be visually verified in real Chrome DevTools before sign-off. Add this to the review protocol.

### 4. Over-engineering trigger-level spans

I built trigger spans (`trigger.page-ready`, `trigger.document-event`, etc.) because OTel has parent-child span trees. In practice:
- Timing was never surfaced anywhere (no dashboard, no filter)
- The only concrete use was HTTP traceparent inheritance — which works fine with a single root span directly
- Parent-child correlation added complexity without benefit

**Takeaway:** Build the minimum surface that serves the real use case. Parent-child spans are a power feature; unless there's a consumer for them, they're premature.

### 5. The build artifacts pollution

`Alis.Reactive.SandboxApp/wwwroot/js/alis-reactive.js`, `Alis.Reactive.SandboxApp/wwwroot/css/design-system.css`, and `Alis.Reactive/assets/js/alis-reactive.js` are regenerated by the `BuildClientAssets` MSBuild target. They should never be committed with functional tracing changes — the local dotnet build rewrites them with the current node_modules Tailwind version (v4.2.1 vs upstream's v4.2.2).

**Takeaway:** Set `git update-index --skip-worktree` on these three files at the start of the session. Don't commit them at all. The PR should have zero lines of diff in these files.

### 6. The rebase conflict cost

After the first attempt was half-done, upstream added 13 commits touching `conditions.ts`, `validation/orchestrator.ts`, `merge-plan.ts` (the same files I was migrating). The rebase hit content conflicts at the migration commit. Manual resolution was tedious but correct.

**Takeaway:** Do small, focused commits. Rebase often. Don't let the branch drift 13+ commits behind upstream.

### 7. The dotnet build rebuilds the bundle

`Alis.Reactive.SandboxApp.csproj` has `BuildClientAssets` BeforeTargets="Build" that runs esbuild + Tailwind. Running `dotnet test ... PlaywrightTests` triggers a build → rebuilds bundles → can introduce tailwind version drift → 500+ test failures from CSS alone. Saw this happen once during this branch.

**Takeaway:** If the build target rebuilds bundles as a side effect, either (a) pin the tailwind version to exactly match upstream, or (b) mark bundles skip-worktree so local rebuilds don't pollute the branch, or (c) disable the BuildClientAssets target for test runs.

### 8. Every review found something

Codex xhigh returned BLOCK on every single phase:
- Phase 1: 2 bugs (NOOP_SPAN parent leak, withSpan coercion)
- Phase 2: 2 migration gaps (missing trigger context, missing status field)
- Phase 3: 5 bugs (rootSpan noop, parallel spans not ended, HTTP span ended twice, parallel sync throw, bundle not synced)
- Final: 4 bugs (span propagation not wired, trigger spans never ended, error contract incomplete for sync throws, scope creep)

**Every block was real.** No false positives. The lesson is not "reviews are slow" — it's "the API shape was complex enough that reviews had to catch nine distinct classes of lifecycle bugs." A simpler API prevents nine classes of bugs from existing at all.

### 9. Do not mark "done" from Playwright counts alone

I claimed "ready to ship" multiple times based on passing Playwright tests. Every time, opening the browser or dispatching Codex xhigh found a real issue. Passing tests are necessary but not sufficient.

**Takeaway:** Final sign-off requires: Playwright green + typecheck clean + vitest green + **manual browser verification of the actual console output** + Codex xhigh clean.

## The v2 Design

### Core principle

**The plan is the source of truth. The runtime visits it. Tracing co-visits with it.**

Every interaction boundary is already in `plan.behaviors[i].startsWhen`. Every IO boundary is already in `request` nodes inside reactions. The tracing module hooks into the runtime's existing execution points and observes — no hand-written instrumentation code in consumers.

### Public surface — ENTIRE module

```typescript
// Scripts/tracing/index.ts
export { tracer, configure } from "./trace";
export { ConsoleSink } from "./sink";
export type { Level, TraceEvent, TraceSink, TraceConfig, ScopedTracer } from "./types";
```

**5 exports. Nothing else.**

The following are **explicitly NOT in the public API**:
- `Span` interface
- `NOOP_SPAN`
- `TraceRoot`
- `SpanData`
- `getRootSpan()`
- `flush()` (handled automatically)
- `ctx.span` field (no such field)
- `tracer().span()` method
- `tracer().withSpan()` method
- Manual span lifecycle of any kind

### Consumer-facing API

```typescript
interface ScopedTracer {
  error(event: string, data?: Record<string, unknown>, err?: Error): void;
  warn(event: string, data?: Record<string, unknown>, err?: Error): void;
  info(event: string, data?: Record<string, unknown>): void;
  debug(event: string, data?: Record<string, unknown>): void;
  trace(event: string, data?: Record<string, unknown>): void;
  enabled(level: Level): boolean;
}

interface TraceConfig {
  level?: Level;
  sink?: TraceSink;
  traceparent?: string;   // from server plan.traceparent
  breadcrumbCapacity?: number;
}
```

**That's the entire surface a dev or plugin author touches.** 6 methods on `ScopedTracer`, 4 config fields, 2 functions (`tracer`, `configure`), 1 sink class (`ConsoleSink`). No more.

### Internal module structure

```
Scripts/tracing/

├── trace.ts              ← ScopedTracer factory, emitEvent pipeline
```

### The interactions module (INTERNAL)

```typescript
// Scripts/tracing/interactions.ts — framework-only, NOT exported from index.ts

import { tracer } from "./trace";
import { formatTraceparent, generateSpanId, generateTraceId, parseTraceparent } from "./context";

interface InteractionRoot {
  readonly traceId: string;
  readonly flags: string;
}

let current: InteractionRoot | undefined;
let configuredFromTraceparent: InteractionRoot | undefined;

/** Called by configure() when server traceparent is present. */
export function setRootFromTraceparent(traceparent: string | undefined): void {
  if (!traceparent) {
    configuredFromTraceparent = undefined;
    return;
  }
  const parsed = parseTraceparent(traceparent);
  configuredFromTraceparent = parsed
    ? { traceId: parsed.traceId, flags: parsed.flags }
    : undefined;
}

/**
 * Wrap an entry-point execution in an interaction.
 * - Starts a trace (uses server traceparent if present, else generates one)
 * - Emits interaction.start / interaction.end / interaction.fail events
 * - Captures sync + async + rejected-promise outcomes
 * - Routes errors to structured error events
 * - Cleans up current on completion
 *
 * Call sites: trigger.ts (runReaction), nothing else directly.
 */
export function run<T>(
  name: string,
  attrs: Record<string, unknown>,
  fn: () => T | Promise<T>,
): T | Promise<T> {
  const prev = current;
  current = current ?? configuredFromTraceparent ?? newRoot();
  const t = tracer("interaction");
  const start = performance.now();
  t.debug("interaction.start", { name, ...attrs });

  const onSuccess = () => {
    t.debug("interaction.end", { name, ms: performance.now() - start });
    current = prev;
  };

  const onFailure = (err: unknown) => {
    t.error("interaction.fail", { name, ...attrs }, err as Error);
    current = prev;
  };

  try {
    const result = fn();
    if (result instanceof Promise) {
      return result.then(
        v => { onSuccess(); return v; },
        err => { onFailure(err); throw err; }
      );
    }
    onSuccess();
    return result;
  } catch (err) {
    onFailure(err);
    throw err;
  }
}

/**
 * Return the current W3C traceparent header, or undefined if no interaction
 * is active. Called by http.ts immediately before fetch() — must be called
 * BEFORE any await to avoid cross-interaction context leakage.
 */
export function currentTraceparent(): string | undefined {
  if (!current) return undefined;
  return formatTraceparent(current.traceId, generateSpanId(), current.flags);
}

function newRoot(): InteractionRoot {
  return { traceId: generateTraceId(), flags: "01" };
}

/** Reset for testing only. */
export function resetForTests(): void {
  current = undefined;
  configuredFromTraceparent = undefined;
}
```

**Total: ~60 lines.** This is the cross-cutting concern in one place.

### trace.ts — Scoped tracer + global state

```typescript
// Scripts/tracing/trace.ts

import type { Level, ScopedTracer, TraceConfig, TraceEvent, TraceSink } from "./types";
import { LEVELS, SEVERITY } from "./types";
import { BreadcrumbBuffer } from "./breadcrumbs";
import { ConsoleSink, serializeError } from "./sink";
import { setRootFromTraceparent } from "./interactions";

let breadcrumbs = new BreadcrumbBuffer(64);
let activeSink: TraceSink = new ConsoleSink();
let activeLevel = LEVELS.off;

export function configure(config: TraceConfig): void {
  activeLevel = LEVELS[config.level ?? "off"];
  activeSink = config.sink ?? new ConsoleSink();
  breadcrumbs = new BreadcrumbBuffer(config.breadcrumbCapacity ?? 64);
  setRootFromTraceparent(config.traceparent);
}

export function tracer(scope: string): ScopedTracer {
  function emit(level: Level, event: string, data?: Record<string, unknown>, err?: Error): void {
    const num = LEVELS[level];

    if (num <= LEVELS.warn || num <= activeLevel) {
      breadcrumbs.push({ time: performance.now(), event, scope, level, data });
    }

    if (num > activeLevel) return;

    // Read current trace-id lazily at emit time — captures the interaction
    // that is actively running, before any subsequent await.
    const { getCurrentTraceId, getCurrentSpanId } = require("./interactions");  // (pseudocode — use a real import)

    const ev: TraceEvent = {
      time: performance.now(),
      event,
      scope,
      level,
      severityNumber: SEVERITY[level as Exclude<Level, "off">],
      data,
      error: err ? serializeError(err) : undefined,
      traceId: getCurrentTraceId(),
      spanId: getCurrentSpanId(),
      breadcrumbs: level === "error" ? breadcrumbs.snapshot() : undefined,
    };

    activeSink.emit(ev);
  }

  return {
    error: (event, data, err) => emit("error", event, data, err),
    warn:  (event, data, err) => emit("warn",  event, data, err),
    info:  (event, data)      => emit("info",  event, data),
    debug: (event, data)      => emit("debug", event, data),
    trace: (event, data)      => emit("trace", event, data),
    enabled: (level)          => LEVELS[level] <= activeLevel,
  };
}
```

Note: `interactions.ts` needs to expose `getCurrentTraceId()` and `getCurrentSpanId()` internally (not in index.ts) so `trace.ts` can read them. Both return undefined if no interaction is active. No circular dependency because `interactions.ts` imports only `tracer` (not `emit`) from `trace.ts`.

### Runtime integration (framework code — 4 files)

**`execution/trigger.ts` — single entry point for reaction execution:**

```typescript
import * as interactions from "../tracing/interactions";
import { executeReaction } from "./execute";

export function runReaction(
  reaction: Reaction,
  plan: Plan,
  ctx: ExecContext,
  triggerKind: string,
  triggerAttrs: Record<string, unknown>,
): void | Promise<void> {
  return interactions.run(triggerKind, { ...triggerAttrs, planId: plan.planId }, () =>
    executeReaction(reaction, plan, ctx)
  );
}
```

**That's it.** No try/catch. No span. No withSpan. No `.end()`. Interactions module handles all of it.

`wireBehavior` then calls `runReaction` with interaction metadata derived from `trigger`:

```typescript
case "document-event":
  t.debug("trigger.wire", { kind: "document-event", event: trigger.event });
  document.addEventListener(trigger.event, (e: Event) => {
    const ctx: ExecContext = { event: (e as CustomEvent).detail ?? e };
    runReaction(reaction, plan, ctx, "document-event", { event: trigger.event });
  }, opts);
  break;
```

Same pattern for page-ready, component-event.

**`execution/server-push.ts` — uses runReaction:**

```typescript
import { runReaction } from "./trigger";

const handler = (e: MessageEvent) => {

```

**`execution/signalr.ts` — uses runReaction:**

**`components/native/native-action-link.ts` — uses runReaction:**

```typescript
function handleClick(event: MouseEvent): void {
  if (event.defaultPrevented || event.button !== 0) return;
  if (event.metaKey || event.ctrlKey || event.shiftKey || event.altKey) return;
  const anchor = (event.target as Element | null)?.closest<HTMLAnchorElement>(SELECTOR);
  if (!anchor) return;
```

### HTTP integration

```typescript
// execution/http.ts — inside executeRequest(), before the await fetch(...)
import { currentTraceparent } from "../tracing/interactions";

const tp = currentTraceparent();  // captured BEFORE any await — must stay sync
if (tp) {
  const headers = (resolved.init.headers as Record<string, string>) ?? {};

const start = performance.now();
```

No span. No `.end()`. Just a header read and a timing event.

The `http.request.fail` error event in the `catch` block stays as today — emitted via `t.error("http.request.fail", {url, method, status}, err)`.

### Event name conventions (unchanged from v1)

- Dotted, noun-first: `boot.start`, `http.request.send`, `reaction.fail`
- Base verb form, no past tense: `.fail` not `.failed`, `.connect` not `.connected`
- Compound adjective states acceptable: `not-found`
- Event names documented in a migration map for grep-ability

### ConsoleSink rendering rules (lessons from v1)

```typescript
// Scripts/tracing/sink.ts

export class ConsoleSink {
  emit(event: TraceEvent): void {
    const tag = `%c[alis:${event.scope}]%c ${event.event} %c${event.level.toUpperCase()}`;
    const styles = [
      "color:#6366f1;font-weight:bold",
      "color:inherit",
      levelColor(event.level),
    ];

    // Inline data JSON for greppability (Playwright + log aggregators)
    // AND human readability. Do NOT also pass as separate arg — causes
    // DevTools to print each log twice (lesson from v1 browser verification).
    const dataStr = event.data ? " " + JSON.stringify(event.data) : "";
    const args: unknown[] = [tag + dataStr, ...styles];
    if (event.error) args.push(event.error);  // error passed separately for DevTools stack trace expansion

    switch (event.level) {
      case "error": console.error(...args); break;
      case "warn":  console.warn(...args); break;
      case "info":  console.info(...args); break;
      default:      console.log(...args); break;
    }

    if (event.traceId) {
      console.log(`  trace: ${event.traceId}  span: ${event.spanId}`);
    }

    if (event.level === "error" && event.breadcrumbs && event.breadcrumbs.length > 0) {
      console.groupCollapsed(`  breadcrumbs (${event.breadcrumbs.length})`);
      console.table(event.breadcrumbs.map(b => ({
        time: b.time.toFixed(1),
        event: b.event,
        scope: b.scope,
        level: b.level,
      })));
      console.groupEnd();
    }
  }

  // No span() method — interactions don't produce SpanData. The dev sees
  // interaction.start/interaction.end events instead, which render like
  // any other event (filterable, greppable).

  flush(): void {}
}
```

## Appendix C — What DOES change from v1

| v1 | v2 |
|----|----|
| `Span` is a public interface | Does not exist in public API |
| `getRootSpan(), NOOP_SPAN, TraceRoot, SpanData` exported | Not exported; span primitives don't exist at all |
| `ctx.span` is an ExecContext field | ExecContext unchanged — no span field |
| `t.span(name)` creates a span the dev owns | Does not exist |
| `t.withSpan(span)` binds a tracer to a span | Does not exist |
| `span.end("ok"/"error")` is a dev responsibility | Handled automatically by `interactions.run` |
| `flush()` exported; dev wires to `beforeunload` | Does not exist — interactions end automatically |
| 4 files each have ~20 lines of manual span lifecycle | 4 files each have 1 line: `runReaction(..., "kind", { attrs })` |
| Spans for trigger, parallel-step, HTTP | Only interactions (at entry points) + HTTP header injection |
| Idempotent `span.end()` with `ended` flag | Not needed — no manual end() to double-call |
| Trigger scope inheritance bug possible | Not possible — there are no cross-file span objects |

## Closing

The v1 branch taught us that **OTel-style span APIs in consumer code are a trap in a runtime where the framework already knows every interaction boundary**. The plan is the source of truth. Tracing observes the walk of the plan. Dev writes events and nothing else. Four files go from 80 lines of boilerplate to 4 lines of plain wiring.

Read the 9 lessons at the top before you write any code. Open the browser before you claim done. Submit every phase to Codex xhigh. This plan is a lot smaller than the v1 plan because the design is smaller.
