Status rules applied:

- **PROVEN**: a real gesture and a visible outcome (message text in the field's `{id}_error` slot or the summary,
  or a blocked or sent request) that would be different if the use case broke. For rule kinds: a failing value
  and a passing value, or at least a failing value whose message is asserted.
- **WEAK**: a test touches it but would still pass if the behavior broke (reason given).
- **PLAN-ONLY**: only an NUnit fixture (in the Playwright project, no browser) asserts plan JSON or metadata.
- **NONE**: no test.

Caveat that applies to many PROVEN condition rows: the "rule skipped" side is usually asserted with
`Not.ToContainTextAsync` / `Not.ToBeVisibleAsync`, which is satisfied by an empty slot; those rows are PROVEN on
the strength of their "rule fires" side plus the crossing of the condition boundary.
