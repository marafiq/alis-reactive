## Reading conventions

- Object names stand for `obj(id)` nodes. `http`, `document` are `builtin(..)`; `xForm` is `builtin(form, id)`; `xStream` is
  `builtin(stream, url)`; `xHub` is `builtin(hub, url)`; `xSlot` is the slot element object for container `x`; `loader`,
  `drawer`, `confirm` are app objects. `U` is the request URL literal rendered by C#.
- `mods(e)` abbreviates `e.defaultPrevented || e.button !== 0 || e.metaKey || e.ctrlKey || e.shiftKey || e.altKey`.
- A request follows section 0.5: `[if (xForm.validate())] { WhileLoading; try { const req = {..}; const res = await http.send({..});
  if (res.ok) S else if (res.status === N) E else A } finally { F } if (res.ok) { Chained } }`. The `try` is written only when
  the row has a Finally; `values` holds the gathered record, `format` is omitted when it is `"json"`.
- Today's exact order, from `R/execution/requests/http.ts:35-56,149-209`: validate (false: return, no WhileLoading, no Finally)
  -> WhileLoading (awaited) -> gather/build (throws: Finally, rethrow) -> fetch -> read body -> one route (exact status, else
  first any-status; status-less failures reach only the any-status error route) -> Finally -> Chained (success only, reads the
  parent response). Section 0.5 reproduces this order; no row needs another order.

## Obligations by object

- **http.send.**
  - Placeholders: fill `{name}` from the same-named value, stringify (Dates ISO), `encodeURIComponent`, keep the member out of the query/body, and throw before fetching when the value is null/undefined: 32-41, 50, 52.
  - GET query: arrays as repeated keys, a missing array adds nothing, a null scalar sends `k=`, join with `&` after an existing `?`, a File throws: 3, 54 (also 2, 24, 42).
  - JSON: `""` becomes null, undefined is dropped, an empty record sends no body and no Content-Type, a File throws: 4-7, 12-14, 17 (all hold today; listed for the rewrite).
  - Form-data: MVC names (`Lines[0].Sku`), repeated entries for arrays, Files with their names, null as `""`, Dates ISO: 8, 9.
  - Body: by Content-Type (JSON / text / none); empty JSON text or no Content-Type gives `body` undefined: 66, 67.
  - Headers: stringify; omit when the value is missing (`gather.ts:92`): needed whenever 26-28 read an absent source.
- **document.** `raise` dispatches synchronously with `detail` (a listener gets `detail`, or the event when it is null): 82, 83, 90, 115, 118. `query` reads (case rule, see A6): 26, 38, 42-50.
- **form.** `values` = every mounted input registered in the composed plan, slot loads included, nested by typed path: 8, 9, 12-15, 91. `showErrors` maps ProblemDetails to inputs, else the summary, and validates on the client when the problem is not an object: 85, 86, 91.
- **slot.** `load`: strip and compose plan scripts, `alis:unmount`, replace, re-create scripts, `alis:mount`, unload the previous load, subscribe, wire live clearing; plan-less HTML unloads: 88, 90, 93, 94, 100, 115, 118. `unload` removes inputs and tests: 96.
- **stream.** One EventSource per URL, counted per owner; retry marker and click-to-recreate: 105, 106.
- **hub.** One connection per URL, counted, start schedule, automatic reconnect, credentials, retry marker, single-argument payload: 101, 108-110, 112.
- **confirm.** `ask` resolves a bool (stated in the design; no extra obligation): 6, 115, 116, 119.
- **loader.** `target` positions it; it re-parents and hides when the target leaves: 99.
- **drawer.** Reset clears content without unloading the slot: 99.
- **element / vendor driver.** Fusion and Tom Select value members, payload `preventDefaultAction`/`updateData`: covered by the components lowering; no HTTP-specific obligation.
- **plan composition.** Slot plans join by planId and recompose on unload: 97. A link's handler must travel with plan-less HTML: 115, 118.
- **owners.** Clearing a container is not an unload: 99. A load into the caller's own slot completes: 100. Slot subscriptions release on unload: 101, 109.

## Ambiguities and contradictions (file:line)

- **A1. Where a link's handler lives.** Sections 0.5 and 4.6 call `NativeActionLink(id, text, url, link => ..)` with no plan, and delete the plan in `data-reactive-link`. Today each link builds its own plan (`NativeActionLinkSerializer.cs:23-47`), and a delegated document listener runs it (`native-action-link.ts:20-49`), which is why links in plan-less, re-injected partials work (`_CareOpsActionRows.cshtml:4-6`, `_NativeActionLinkGrid.cshtml`). Today link IDs are generated (`NativeActionLinkIdGenerator`); the design makes them the developer's.
- **A2. Law 4 versus today's unload.** Today unload only aborts listener wiring (`applied-plans.ts:73-78`; the signal reaches only `wireTrigger`, `R/execution/triggers/trigger.ts:34`; `execute.ts` never reads it), so in-flight requests finish. Law 4 stops them at the next `await`. That changes reload-during-flight (row 95 has no test), and it makes rows 99 and 100 depend on clearing not being an unload and on `slot.load` finishing.
- **A3. Slots.** Section 4.0.1 lists "a slot" as an app object "with a fixed ID", but slot IDs are developer containers (`Into("address-container")`). The design does not say how `load`/`unload` are defined on arbitrary containers. It never mentions `alis:mount`/`alis:unmount` (`inject.ts:32-40`), which the runtime treats as its public contract with app bundles. Section 8 makes slot loading async; today injection is synchronous (`execute.ts:202-213`).
- **A4. `Form()` versus the old every-input gather.**
  - The old every-input gather was plan-wide: every registered, mounted input of the composed planId (`gather.ts:147-165`), not a container. Forms are keyed by id (`builtin(form,id)`, section 9 `inputs.form`), and the pages that gathered every input without a validator (MedicationPass, MedicationOrder, OutingRoster) have no form id. The C# `Form()` that replaced it keeps that scope: the inputs the view and the partials composed with it rendered through `Html.InputField`, while they are on the page (`Alis.Reactive/PlanAuthoring/Requests/GatherBuilder.cs`, `Form()`).
  - Form-data needs MVC name text, while JSON needs typed nesting. A plain nested record cannot tell a dictionary from an object when it is flattened (`PlanTerms.cs:145-147` carries both).
  - Today authored fields are written before the gathered inputs (`gather.ts:62-63`), so the spread must come last.
- **A5. The route-value rule.** Section 4.6 keeps a placeholder-matched member out of the body. PivotView sends `currentView` in both the path and the body (`V/Components/Fusion/PivotView/Index.cshtml:59-61`), which that rule cannot express. The design gives no case rule for matching; today it is ordinal (`RequestRouteTemplate.cs:19,31`; `url-template.ts:1-8`), and request-class members camel-case.
- **A6. `document.query`.** It is designed case-insensitive, with a repeated key read as an array. Today it is case-sensitive and returns the first value (`evaluate.ts:178-183`). A missing typed value stays null today (`applyShapeWhenPresent`); a `toNumber(undefined)` that follows `shape-convert.ts:161` returns 0 and would send "0" instead of throwing (row 38/41).
- **A7. Status 0.** The design says "status 0 when no response came", but today a response whose JSON fails to parse is also treated as no response, because the body is read inside the fetch `try` (`http.ts:87-104`).
- **A8. Wire formatting needs shapes.** Today it uses each source's declared shape: date timestamps become ISO (`R/browser-objects/runtime-shape.ts:66-76`), `""` becomes null in JSON (`request-payload-writer.ts:235-240`). The record passed to `http.send` carries no shapes, so `http.send` must decide from runtime types.
- **A9. Response handles change meaning.** Today they are dynamic: `PayloadSource.Success()` reads the current response context (`http.ts:221-230`; `R/browser-objects/execution-context.ts:59-66`), so an outer handle read inside a nested route reads the inner response; lexical binding changes that. Section 4.6 shows `Chained(next => ..)` without the response, though Law 2 says the chained request reads it (row 70).
- **A10. The request snapshot.** Section 0.5 declares `req` inside the `try`, so `finally` cannot read it; Law 2 extends scope only after the `try`. Today Finally runs with the request context (`http.ts:55,182-192`), and a form-data snapshot is `{}` (`http.ts:232-238`). No builder exposes the snapshot (`Alis.Reactive/PlanModel/Values/Source.cs:73` has no caller), so no row breaks.
- **A11. Owners after an SSE retry.** The design says today's connection policy stays and is counted per owner. A manual SSE retry rewires behaviors without their owner's abort signal (`server-push.ts:27-33`), so a retried slot subscription is never released. Hub counting is per subscription (`signalr.ts:125-141`).
- **A12. Route order is a builder duty.** Section 0.5 shows authored order; today exact status beats any-status whatever the order, and only the first OnSuccess runs (`http.ts:288`). Error arms must sit behind `!res.ok` even without OnSuccess.
