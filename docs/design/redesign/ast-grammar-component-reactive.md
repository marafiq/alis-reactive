# component-reactive

Grammar (AST edges) for the cluster: `Html.InputField(...)` -> `.FusionXxx(b => ...)` / `.NativeXxx(b => ...)` component-builder -> `.Reactive(plan, evt => evt.X, (args, p) => ...)`.

Every row is a REAL public method read from `.cs` source with a `file:line`. Source is the authority; nothing inferred from sandbox usage.

## Reading the table

- **Receiver** — the type the method extends / is declared on (the left of the dot).
- **Member(params)** — the public method name and its parameter shapes.
- **Returns** — declared return type.
- **Callback** — the callback param type if any (FLAG: an `Action<TArgs, PipelineBuilder<TModel>>` hands back a `PipelineBuilder` — that is a NESTING / recursion point into the pipeline grammar; an `Action<XxxBuilder>` nests into the component builder grammar).
- **ReturnsSelf** — `yes` if it returns its own receiver type (chainable / repeatable). FLAG: `ReturnsSelf=yes` on `.Reactive` proves multiple `.Reactive` calls CHAIN for multiple events on one component.
- **Source** — relative `file:line` of the public method declaration.

## Cluster shape (uniform)

Every `*ReactiveExtensions.cs` exposes exactly one `Reactive<...>` method with this shape (FusionSmartTextArea is the only exception — see its section):

```
<Builder>.Reactive(
    ReactivePlan<TModel> plan,
    Func<<Comp>Events, TypedEvent<TArgs>> eventSelector,   // the event-selector param: evt => evt.X
    Action<TArgs, PipelineBuilder<TModel>> pipeline)        // the (args, p) callback — NESTS into PipelineBuilder
    -> <Builder>                                            // RETURNS the component builder -> .Reactive chains for multiple events
```

`TypedEvent<TArgs>` is the event descriptor returned by the selector; `<Comp>Events.Instance` is the singleton the selector reads. `eventSelector` and `pipeline` are sometimes named `on` / `pipeline` in source (FusionChipList, FusionMention, FusionSmartTextArea) — same shape.

## Grammar summary

- **Entry edge** — `Html.InputField(...) -> InputBoundField<TModel,TProp>` (2 overloads).
- **Component-builder edge** — `InputBoundField<...>.FusionXxx/.NativeXxx(Action<XxxBuilder> build) -> void`; the `build` callback NESTS into the component builder grammar (props, `.Fields`, `.Reactive`).
- **`.Reactive` edge** — `<Builder>.Reactive(plan, Func<<Comp>Events, TypedEvent<TArgs>> eventSelector, Action<TArgs, PipelineBuilder<TModel>> pipeline) -> <Builder>`. The `pipeline` callback NESTS into `PipelineBuilder` (recursion into the pipeline grammar). `ReturnsSelf=yes` on all 56 builder `.Reactive` methods proves multiple `.Reactive` CHAIN for multiple events on one component. The lone exception is `FusionSmartTextArea`, whose 2 `.Reactive` overloads extend `ReactivePlan<TModel>` and return `void`.
