# Button Audit Report

Status: audited and closed. `FusionButton` is fully onboarded. Every public typed
member has deterministic raw EJ2 evidence, an explicit C# name decision, an
authoritative primitive mapping, a vertical-slice file, and focused typed DSL
Playwright proof bound to a fails-when-broken assertion. The generated typed API
coverage matrix is `audited` with every row `row-proven`.

## Accepted Members

The Button slice onboards the post-render runtime surface; initial render
configuration stays on the Syncfusion `ButtonBuilder`. `FusionButton` is a
non-input display/action component and registers no form binding.

- `FusionButton(...)` — the HTML render helper, wrapping `ButtonBuilder` and carrying the component id.
- `SetContent(string)` / `Content()` — writes and reads `content`; chains `dataBind()` to repaint the label.
- `SetDisabled(bool)` / `Disabled()` — writes and reads `disabled`.
- `SetIcon(string, FusionButtonIconPosition)` — writes `iconCss` and `iconPosition` together.
- `SetCssClass(string)` / `CssClass()` — writes and reads `cssClass`.
- `SetPrimary(bool)` / `IsPrimary()` — writes and reads `isPrimary`.
- `SetToggle(bool)` / `IsToggle()` — writes and reads `isToggle`.
- `Click()` — calls `click()`; latches `e-active` when the button is a toggle.
- `FocusIn()` — calls `focusIn()`; moves keyboard focus onto the button.

## Excluded Candidates

- `created` event — builder-owned DOM-native lifecycle hook with no focused Senior Living payload use case; the Button slice exposes no event surface.
- `enableHtmlSanitizer` property — builder-owned static configuration (`discovery/public-api-surface.json` marks `builder.covered = true`); no post-render read/write proven necessary.
- `locale` property — `@private` culture/i18n configuration (`node_modules/@syncfusion/ej2-buttons/src/button/button.d.ts:96`); the plain EJ2 Button registers no localized strings, so it changes nothing visible. Excluded with evidence in `discovery/parity-accounting.json`.
- `destroy()` method — lifecycle cleanup, not plan behavior (`discovery/public-api-surface.json` classifies it `skip`).

## Remote Data Lane

`Button` is a non-input action/display control: it binds to no model property,
emits no value, and has no remote binding, paging, filtering, lookup,
virtualization, or server-query lane to onboard. The realistic remote workflow for
an action button is recording the action it represents, which the gather rows
prove: the Daily Wellness Check-In POSTs `action`, `priority`, `recommended`, and
`followUp`, and the care-team member sees the server confirmation. This satisfies
the remote-behavior expectation for this component class (see
`references/automation-gates.md` Gate 6 applicability — Button is not a
board/grid/scheduler/list/tree).
