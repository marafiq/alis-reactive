## Accepted Members

`FusionAccordion` is a non-input container component. The slice onboards the post-render
runtime surface; initial render configuration (the panel set, expand mode, templates,
dimensions) stays on the Syncfusion `AccordionBuilder`.

- `FusionAccordion(... ReactivePlan<TModel> plan, string elementId, Action<AccordionBuilder> build)` — the render helper that carries the controlled container id into the plan.
- `FusionAccordionEvents.Expanded` — the `expanded` event selector, with `Reactive(...)` wiring through `ComponentEventOnboarding.Wire`.
- `FusionAccordionExpandedArgs.Index` — the zero-based index of the panel that expanded or collapsed, read from `event.index`.
- `FusionAccordionExpandedArgs.IsExpanded` — expand (true) versus collapse (false), read from `event.isExpanded`.
- `ExpandItem(this ComponentRef<FusionAccordion, TModel> self, bool isExpand, int index)` — calls `expandItem(isExpand, index)` to expand or collapse the addressed panel.
- `EnableItem(this ComponentRef<FusionAccordion, TModel> self, int index, bool isEnable = true)` — calls `enableItem(index, isEnable)` to add or remove the disabled overlay on the addressed panel.

## Excluded Candidates

- `expanded.content`, `expanded.element` — browser-owned `HTMLElement` payload members; excluded from the public typed payload rather than exposed as `object`/`dynamic`.
- `expanded.item` — vendor `AccordionItemModel`; panel composition is builder-owned, not a runtime payload value.
- `expanded.name` (inherited `BaseEventArgs.name`) — duplicate event identity metadata; the `Expanded` selector already owns the event identity.
- `expanding`, `clicked`, `created`, `destroyed` events — `expanded` is the proven panel-state event; `expanding`/`clicked` carry a `cancel` flag with no focused Senior Living use case yet; `created`/`destroyed` are DOM-native lifecycle events (`event-payload-surface.json`).
- `addItem`, `removeItem` methods — builder-owned structural composition; their argument is a vendor `AccordionItemModel`/loose `Object`, which no DSL primitive constructs (`discovery/parity-accounting.json`).
- `hideItem` method — a near-duplicate of `enableItem` availability control; the journey locks/unlocks sections through `EnableItem` (`discovery/parity-accounting.json`).
- `select` method — sets keyboard focus to a header only; returns void and yields no value to branch/gather/display (`discovery/parity-accounting.json`).
- `animation`, `dataSource`, `enableHtmlSanitizer`, `expandedIndices`, `expandMode`, `headerTemplate`, `height`, `items`, `itemTemplate`, `width` — builder-owned static configuration (`discovery/public-api-surface.json` marks each `builder.covered = true`); no post-render read/write proven necessary.
- `destroy()` method — lifecycle cleanup, not plan behavior (`discovery/public-api-surface.json` classifies it `skip`).

## Remote Data Lane

`Accordion` is a layout/container component, not a data-capable board/grid/scheduler/list/tree:
it organizes declared panels and emits panel-state events. It has no remote binding, paging,
filtering, lookup, virtualization, or server-query lane to onboard. The realistic remote
workflow for an accordion is loading a panel's detail on demand when the resident opens it,
which the journey proves: opening the monthly-charges section fires `expanded` with `index 1`,
which drives an HTTP GET whose response is injected into the panel and the resident sees this
month's charges. This satisfies the remote-behavior expectation for this component class
(see `references/automation-gates.md` Gate 6 applicability — Accordion is not a board/grid/scheduler/list/tree).
