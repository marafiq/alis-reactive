# FusionCheckBox public API coverage

## Which contract runs on the care pages?

The umbrella browser distribution and both ASP.NET packages use 33.1.47 (package-lock.json and Directory.Packages.props). The installed constituent packages are @syncfusion/ej2-buttons 33.1.44 and @syncfusion/ej2-base 33.1.45. The initial inventory was taken at a0b69dfaf. The final inventory has the same vendor roots, signatures and installed versions, and includes the completed C# declaration. Its compiler resolved five reachable shapes, with 37 root names and 64 root read, write, event or call operations. The three payload fields generate six further operations, the React context four, and the two string indexes four. The final declaration directly projects 28 root operations on 18 names: ten read/write settings, one element read, six zero-argument calls and the change event. All three payload members have typed reads. The table below accounts for the remaining root operations and the limits on these typed paths. The FusionCheckBoxWave landing packet retains operations.json and operations-final.json. The latter records the C# name, operator, source and individual signature line in both shipped manifests. Both host manifests list the check box and payload at lines 168–199 and its render helper overloads at 1564–1565 in the isolated worktree.

S and SJ refer to Buttons src/check-box/check-box.d.ts and check-box.js. E is Buttons src/common/common.d.ts. C and CJ are Base src/component.d.ts and component.js. B and BJ are Base src/base.d.ts and base.js. The numbers following each abbreviation are source line numbers. The HTMLInputElement, HTMLElement and Event returned at the DOM boundary remain the standard DOM types.

FusionComponent.cs:18–22 declares EJ2 instance lookup and listener attachment/release. FusionCheckBoxHtml.cs:16–28 first applies the checked value from field.ValueJson and the registered MVC name before running the configurable callback. The net10 and net48 partials both call CheckBox(field.Id) and field.Render<FusionCheckBox>. The existing X1006 independently shows both model starts using the default helper. The new net10 care screens exercise the configurable helper. The builder-net10.txt and builder-net48.txt extracts contain 15 XML entries per wrapper. Both render partials call Checked(bool) through the shared helper even though that method has no CheckBoxBuilder XML entry in either extract. Both helper overloads accept InputField<TModel, bool> and render the same registered input. Nullable bool is outside this helper. A nullable enclosing model can still withhold the leaf. D17.13 specifies JSON null in that case. FusionCheckBoxHtml.cs:30–33 maps every token except true to unchecked. X1006 exercises a present bool leaf in both states. A missing enclosing model is source evidence only on this checkbox. EJ2’s separate indeterminate flag does not encode a nullable C# member.

Staff use four pages under admission-clinical. The badge desk decides whether a photo can be issued, the signed record supplies the bool to the application endpoint, the release form sends its independent native filing code, the print desk prepares resident-facing material, and the workstation holds a draft locally. The open live-validation case used a separate badge application. All X numbers in this document refer to M21.F10.

## Which forms have a concrete limitation?

- Live validation after ordinary checkbox activation. A staffed badge desk requires signed permission for a badge with a photo. The attempted typed path used a real `PhotoBadgeRules` registered with `AddReactiveFluentValidation`, `RuleFor(badge => badge.PhotoConsent).Equal(true)`, a bound FusionCheckBox inside `Html.BeginRequestContainer`, and the existing `ComponentInput.Of(Checked, committedBy: Change)`. A delegated `Click()` visibly withdrew permission yet left the required inline message absent. The net10 result and ARIA snapshot are in green-1317.log. Ordinary click, Space, direct caption activation and delegated click each emitted EJ2 change followed by a native input and then native change in the pinned Chromium trace (verified-activation.log). Execution/start.ts:47 subscribes the live check to the EJ2 commit. Validation/page.ts:10–14 clears the field message in the native input capture handler. CheckBox SJ121–150 and 600–602 produce the vendor change in the click turn. The trace distinguishes that behavior from the outer padded wrapper, which emitted only the vendor change. A synthetic wrapper-only gesture would not prove the ordinary accessible checkbox interaction. X1317 was an unlanded candidate. The unproven-1317 folder holds the real validator, view and test. X1301 covers the distinct checked-value gather. A visible commit-driven field failure for ordinary native activation remains open under D12.7 and D16.15.
- Whole-map and indexed access. The proposal Property<WrapperAttributes> would preserve a safe title when passed as a literal, but Property.Set(ITypedSource<T>) passes the whole existing live object onward (Alis.Reactive/Declarations/Members.cs:82–87 and ValuesAndSources/HeldForm.cs:94–100). CheckBox SJ561–593 forwards id and name onto the control, and sends other unrecognized keys to its wrapper. The owner’s existing map exclusion in switch-coverage.md applies to this identity risk (switch-coverage.md, final attribute-map decision). Render-time HtmlAttributes supplies the trusted aria-label in X1310 and X1311. Setting or reading a bounded individual map key through the frozen live surface remains unsupported.
- Changing an already remembered worksheet to private mode. After opt-in the vendor attaches pagehide in CJ181–193. Clearing the flag before refresh prevents CJ105–115 from removing the listener. The page presents the choice before enabling persistence and closes the storage controls after opt-in. The one-visit case starts in a fresh context. It does not erase an older stored worksheet or prove disabling an active listener.
- Element and root replacement. Writing element would move the registered MVC input away from its binding. A user can inspect the anchored native input or the result of getRootElement, and can end the enhancement through Destroy.
- Vendor implementation APIs. JSDoc-private getPersistData, onPropertyChanged, constructor, private helpers and protected rendering/wiring are absent from the public graph. Some returned DOM classes have hundreds of members. The owner’s DOM boundary retains the shallow operations used here.
- The transient distinction between declared optional or nullable event members and observed MVC data is retained. The package probe ej2-payload-checkbox-change records checked:boolean,event:object,name:string. No supported MVC activation was found that hands an absent event, an absent checked field or an absent category.

## How does the sheet render a reading direction?

The sheet’s two layout choices set a real translated photo permission caption, the named Before/After value and the vendor RTL property. Both the checkbox and its wrapper reference the visible “Photo identification permission” legend. X1307 finds the labelled control containing the native checkbox and checks its actual class and caption on each sheet. Preparing a print order uses the live enum and direction together. The verified-layout.log probe checks input, caption, mark in the Arabic edition and input, mark, caption in the English edition. The verified-blank-caption.log probe changes a default uncaptioned checkbox. Setting Before alone gives Chromium’s insertBefore TypeError. Assigning the Arabic caption first and then Before renders input, caption, mark. SJ390–401 unconditionally repositions the existing caption. Its DOM inspection is vendor evidence. The conformance test uses only user-located controls and their visible text or state. X1306 checks the large-print class on that control. The sheet’s CSS enlarges the caption, and the print order uses the live CssClass value.

## Which framework contracts carry the work?

The view’s set, get and call expressions use the existing component driver and listening contract in D17.3/D17.5. D11.4 and Execution/Run.tla’s WritesAfterTheTurnAreRefused govern the immediate payload read. OwnershipAndState/Ownership.tla’s HandlersHearInTheOrderTheySubscribed invariant governs ordinary vendor subscriptions. D14.3 and D17.13 supply the field identity and checked start. The request uses the existing request lane. The component adds no asynchronous ordering or plan production. The native input sequence in the open live-validation case is an observed browser boundary, with no new framework timing contract claimed.
